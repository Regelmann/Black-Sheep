# KEYFOODS V56.15 — COMMERCE PREMIUM

## Canonical commercial logic
1. Excel price list -> Supabase stock -> frontend.
2. Price priority: negotiated override -> client historical -> list -> consult.
3. Catalog priority: habitual/replenishment -> opportunities/focus -> special/short coverage -> remaining stock.
4. Replenishment: median historical quantity; cadence from distinct order dates; trigger at >=85% of median cadence.
5. Stock gate: public orders reject SIN_STOCK/VENCIDO/zero operational stock.
6. Public order server recalculates price and validates stock; frontend values are never trusted.
7. Orders enter pedidos with fuente=catalogo_publico and estado=recibido.
8. External bridge fields support Keylogistics without pretending there is a SAP API.
9. The public RPC exposes aggregates, not raw customer order history.

## Deployment
Run:
scripts/SUPABASE_FIX_STOCK_PRECIOS.sql
scripts/SUPABASE_COMMERCE_V56_15_PREMIUM.sql

Then deploy the frontend.

## Note
The migration assumes existing commerce tables from V56.4 and existing stock columns used by the current app. Test in Supabase SQL editor before production.
