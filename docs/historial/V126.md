## 🔴 Por qué el incremental nunca funcionó

Lo encontré, y no era lo que ninguno de los dos pensaba.

**El código estaba completo y era correcto:**

```
línea   11  "Excel nuevo se SUMA a public.ventas_lineas (no reemplaza el mes)"
línea 3143  fetch_ventas_supabase()      → lee el histórico, paginado
línea 3446  merge_ventas_incremental()   → fusiona Excel + histórico,
                                            con anti-doble-conteo
```

**Lo que faltaba era la tabla.** El propio ciclo lo venía avisando en cada
corrida:

```
⚠ tabla public.ventas_lineas no existe → corré SUPABASE_VENTAS_LINEAS.sql
  sin histórico: el Excel se usará solo (peligroso si es parcial)
```

**Ese archivo nunca estuvo en el repo.** Sin tabla no hay dónde acumular, así
que cada corrida caía a "solo Excel" — y por eso subir la venta de un día
dejaba a todos los clientes sin historial y sin promedio.

`sql/41_VENTAS_LINEAS.sql` la crea, con el esquema exacto que el ciclo escribe.

### Cómo queda

```
corrida 1 · Excel del mes completo  → guarda cada línea
corrida 2 · Excel de HOY solamente  → SUMA; el promedio y el MTD
                                       salen del histórico guardado
```

**Idempotente:** `linea_id` es un SHA1 de cliente + fecha + documento + sku +
monto + cantidad. Subir dos veces el mismo archivo **no duplica nada**.

El diagnóstico del final te lo confirma: después de subir el Excel de un día,
el mes debe **crecer**, no reiniciarse.
