# v-BS-PLATFORM-V12.8 — Revertida la limpieza de CSS

**543/543 tests · build ✓ app · build ✓ web**

## 🔴 Rompí la UI en V12.7. Revertido.

En tu captura de V12.7:

- La pastilla de zona activa es **un óvalo naranja sin texto**
- Las otras dos son **cajas blancas cuadradas**, no el segmented
- El contenido se corta a la derecha (`$35.` · `KeyF`)
- La barra inferior tiene íconos gigantes y **ninguna etiqueta**

**Fue mi limpieza de CSS.** Borré 242 bloques con este criterio:

> "si el selector aparece en una hoja posterior, este bloque nunca se
> aplica → se puede borrar"

**Está mal, y es un error conceptual básico.** La cascada de CSS resuelve
**propiedad por propiedad**, no bloque por bloque:

```css
hoja A:  .bs-seg-btn { color: #fff; font-weight: 700 }
hoja B:  .bs-seg-btn { padding: 0 10px }
```

La hoja B **no pisa el color**: sólo agrega padding. Borrar el bloque de A
porque "B lo redefine" borra el color — y el botón queda con texto blanco
sobre fondo blanco, o sin texto visible sobre naranja.

Eso es exactamente lo que se ve en la captura.

### Lo peor: los 544 tests pasaron

Contraste, táctil, desborde, geometría, cascada. **Ninguno detectó que la UI
estaba rota.** Verificaban que las reglas existieran, no que el resultado se
viera bien.

Es la lección más cara de esta sesión: **una limpieza de CSS necesita
verificación visual**. Los tests unitarios no alcanzan.

### Qué se conservó

Revertí las 7 hojas, pero **sin perder nada de V12.x**: los estilos de
"Dónde ir ahora", proyección del mes, Hoy en terreno, prospectos en Admin y
el catálogo siguen ahí.

Y el arreglo que **sí** era correcto se mantiene: `#c2410c` pasa por
`var(--brand)` en todas las hojas. Sin eso, el catálogo del próximo tenant
saldría naranja KeyFoods.

`cascada.test.js` quedó reescrito: vigila que la cascada **no empeore**
—tope de `!important`, de líneas, de hojas— en vez de exigir una limpieza
agresiva que ya sabemos que rompe.
